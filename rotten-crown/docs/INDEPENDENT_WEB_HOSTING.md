# استضافة ويب مستقلة لـ Rotten Crown

هذا الإعداد ينشر نسخة اللعبة من فرع Arena فقط، من دون نسخ ملفات اللعبة إلى أي فرع آخر أو استخدام موقع GitHub Pages الحالي. فرع النشر المقصود هو `arena/29bc081f-godot-mcp`.

## إعداد موقع ثابت يتحدّث مع الفرع

1. في Netlify اختر **Add new project → Import an existing project** واربط المستودع `mahmoud70004-debug/godot-mcp` من واجهة الخدمة نفسها. لا ترسل كلمات مرور أو رموز وصول في المحادثة.
2. عيّن **Production branch** إلى `arena/29bc081f-godot-mcp` تحديدًا، لا الفرع الافتراضي. عندها يبني Netlify تحديثات هذا الفرع فقط.
3. يقرأ Netlify ملف `netlify.toml` في الفرع: المجلد الأساسي `rotten-crown`، وأمر البناء `bash tools/prepare_web_host.sh`، والمجلد المنشور `build/netlify` نسبةً إلى المجلد الأساسي. ينشئ الأمر نسخة من ملفات Rotten Crown اللازمة في `docs/` فقط، ويتحقق من حجم PCK؛ لا ينشر Under One Roof ولا يثبت تبعيات خادم MCP.
4. بعد إنشاء الموقع ونجاح النشر، استخدم رابط `netlify.app` الذي يظهر لك. يُحدَّث الموقع تلقائيًا عند دفع تغييرات إلى فرع Arena. ملفات `docs/` هي تصدير الويب؛ بعد تغيير اللعبة يجب إعادة تصديرها قبل الدفع، وإلا سينشر المضيف النسخة المخبوزة السابقة.

يضيف سكربت تجهيز الموقع ملف `_headers` لترويسات COOP/COEP وعدم تخزين HTML وservice worker وPCK مؤقتًا على CDN. لا يغيّر هذا إعدادات Godot أو المصيّر. الـAPK المتاح حاليًا هو الإصدار السابق، وتوضح صفحة اللعبة ذلك.

اختُبر إعداد البناء نفسه محليًا باستخدام `netlify-cli 27.16.2 build --offline` ونجح في قراءة `netlify.toml` وتشغيل أمر التجهيز من المجلد الأساسي الصحيح. هذا الاختبار لا يثبت ربط Git أو تشغيل موقع دائم؛ يجب فحصهما بعد إنشائه.

## اختبار مؤقت أُجري في 2026-11-02

لم تظهر ترويستا COOP/COEP مباشرة في استجابات هذا النشر المجهول، رغم وجود `_headers`؛ حقق اختبار المتصفح نجاحًا مع service worker الحالي. يجب اختبار ترويسات الموقع الدائم وتشغيل اللعبة عليه بعد ربط Git، ولا يُفترض تطابق سلوك النشر المجهول مع بناء Netlify المتصل بالمستودع.
