# Rotten Crown — المرحلة الأولى

نموذج أولي مستقل للعبة ثلاثية الأبعاد على Godot 4.4، داخل مجلد منفصل عن خادم Godot MCP الموجود في المستودع. هذه مرحلة **هيكل واختبار بصري** وليست لعبة مكتملة أو نسخة Android جاهزة للتوزيع.

## التشغيل

1. افتح Godot 4.4 أو أحدث متوافقًا مع Godot 4، واختر **Import** ثم `rotten-crown/project.godot`.
2. شغّل المشروع بـ **F5**. يبدأ في أطراف ڤالدرون؛ اتبع الطريق نحو البوابة. الاقتراب من الرقوق وإجراء USE يضيفها إلى الحقيبة. يوجد كائن تجريبي على الطريق يمكن ضربه ثلاث مرات.
3. على الحاسوب: `WASD` للحركة، انقر لالتقاط الفأرة ثم حركها للنظر، زر الفأرة الأيسر أو `Space` للضرب، `Shift` للإمساك بالوضع الدفاعي، `E` للتفاعل، `Tab` أو `I` للحقيبة، و`Esc` لتحرير الفأرة.
4. على الهاتف: ذراع ثابتة يسارًا، واسحب المساحة اليمنى للنظر، واستخدم STRIKE وGUARD وUSE وBAG. يدعم النموذج اللمس المتعدد للحركة والنظر معًا، وGUARD يستمر ما دام الزر مضغوطًا. الواجهة حاليًا بالإنجليزية كمحتوى مؤقت.

من جذر المستودع، لتشغيل اختبار المنطق:

```sh
godot --headless --path rotten-crown --script res://tests/smoke.gd
```

الاختبار يفحص إنشاء المشهد وجمع عنصر مرة واحدة والحقيبة وإصابة الكائن. لا يغني عن الاختبار البصري واختبار اللمس على جهاز فعلي.

## معاينة الويب السريعة

لتشغيل المعاينة من جذر المستودع، استخدم Python 3:

```sh
python3 rotten-crown/preview/server.py --host 127.0.0.1 --port 8080
```

افتح `http://127.0.0.1:8080` على الجهاز نفسه. للوصول من جهاز آخر تحتاج إلى استضافة أو وكيل HTTPS متاح له؛ `127.0.0.1` على الهاتف يشير للهاتف نفسه. في Arena يمكن تشغيل الخادم على `0.0.0.0` واستخدام رابط المعاينة الذي توفره البيئة. الرابط **مؤقت** ويعمل ما دامت جلسة المعاينة والخادم نشطين، وليس نشرًا عامًا دائمًا. بعد تعديل السكربتات أو المشاهد، أعد تحميل الصفحة للحصول على أحدث نسخة؛ لا حاجة إلى إعادة التصدير لهذا النموذج الحالي.

هذه معاينة تطويرية، **وليست تصديرًا رسميًا من محرر Godot**: يضع الخادم ملفات المصدر المدعومة في PCK مؤقت عند كل طلب ويشغلها بقالب Godot Web debug أحادي الخيط 4.7.2، بينما يستهدف المشروع Godot 4.4+. عند أول تشغيل يُنزّل قالب الويب من نسخة مثبتة من مرآة على GitHub، ويتحقق من SHA-256 ويخزنه في `.godot/` (نحو 37 ميغابايت، غير مضمنة في Git). ملفا AudioWorklet في مجلد المعاينة من مصدر Godot 4.7.2 وتبقى رخصتهما في ترويساتهما.

المعاينة الحالية تدعم `project.godot` وملفات `.gd` و`.tscn` و`.tres` و`.gdshader` داخل `scripts/` و`scenes/` فقط، وتستخدم قائمة أصناف عامة فارغة؛ لا تدعم `class_name` أو استيراد الصور والصوت أو الموارد المحولة. عند إضافة هذه الميزات يجب توسيع مسار المعاينة أو استخدام تصدير Web حقيقي من المحرر، كما ينبغي اختبار إصدارات Godot المستهدفة وAndroid مباشرة. الخادم مخصص للتطوير ولا يوفر المصادقة أو الحماية المطلوبة للاستضافة الإنتاجية.

اختبار بناء الحزمة:

```sh
cd rotten-crown/preview && python3 -m unittest -v
```

## ما يتضمنه النموذج

- منظور أول، تصادم وحركة بسيطة، سيف هندسي متحرك، هجوم محدود المدى ووضع دفاعي يقلل السرعة. الدفاع لا يصد الضرر بعد، ولا توجد صحة أو هجمات مضادة.
- مشهد ليلي ضبابي: طريق، بيوت مهجورة، غابة جرداء، قبور، بوابة، قلعة بعيدة وآثار دم ومادة خضراء. الهندسة والخامات مؤقتة وليست أصولًا فنية نهائية.
- كائن مشوه ثابت تجريبي يتمايل ويتلقى الضربات؛ لا يوجد ذكاء اصطناعي أو زعماء بعد. مقتنيان قصصيان وحقيبة في الذاكرة فقط، بلا حفظ.
- عرض العالم عبر SubViewport منخفض الدقة مع تصفية أقرب جار وواجهة منفصلة أكثر وضوحًا. دقة العالم تتغير مع حجم النافذة باستخدام `stretch_shrink`، وليست محاكاة بكسل آرت نهائية.
- إعداد أفقي وواجهة لمس مبدئية وGL Compatibility لتسهيل استهداف الأجهزة المحمولة. لم يُضبط تصدير Android أو يختبر الأداء أو اللمس الفعلي بعد.

## بنية الملفات

- `scenes/main.tscn`: نقطة الدخول.
- `scripts/main.gd`: تركيب المشهد وربط التفاعل والحقيبة.
- `scripts/world.gd`: بناء مساحة الاختبار والكائنات المؤقتة.
- `scripts/player.gd`: الحركة والكاميرا والسيف.
- `scripts/hud.gd`: الرسم واللمس المتعدد واختصارات الحاسوب.
- `scripts/pickup.gd`, `scripts/enemy.gd`: نماذج بيانات/سلوك أولية للاستبدال تدريجيًا بمشاهد وموارد مستقلة.
- `docs/ROADMAP.md`: اتجاه القصة وخطة المراحل.

المشهد يُنشأ برمجيًا في وقت التشغيل؛ يمكن تعديل مواضع وخامات العناصر في `world.gd`. يُفضّل تحويل المناطق والمخلوقات والعناصر لاحقًا إلى مشاهد وموارد قابلة للتحرير، بدل توسيع مولّد الاختبار إلى اللعبة الكاملة.

## Android لاحقًا

ثبّت قوالب التصدير المطابقة لإصدار Godot وAndroid SDK وJDK وفق توثيق المحرك، ثم أنشئ Android export preset واضبط اسم الحزمة والتوقيع. اختبر الأداء والتصادم واللمس المتزامن وتنوع نسب العرض والمناطق الآمنة على أجهزة حقيقية قبل إنشاء APK/AAB. لا يتضمن هذا المشروع مفاتيح توقيع أو إعداد تصدير جاهزًا.

## نشر المعاينة على GitHub Pages

ملف `.github/workflows/rotten-crown-pages.yml` يبني معاينة ويب ثابتة وينشرها عند دفع التحديثات إلى فرع جلسة Arena `arena/9d0420eb-godot-mcp`. يلزم ضبط **Settings → Pages → Build and deployment → Source** على **GitHub Actions**، والسماح لهذا الفرع بالنشر في بيئة `github-pages` إن كانت عليها سياسة فروع. تستبدل هذه الطريقة موقع Pages الحالي للمستودع. التغييرات غير المدفوعة لا تظهر في الرابط؛ بعد نجاح Workflow يمكن تحديث الصفحة للحصول على الإصدار المنشور. رابط Pages عام ومستقل عن عمر جلسة المعاينة المؤقتة.

يمكن توليد ملفات الاختبار الثابتة محليًا دون إدخالها في Git:

```sh
python3 rotten-crown/preview/build_static.py /tmp/rotten-crown-site
```

تنطبق حدود معاينة التطوير المذكورة أعلاه على النسخة المنشورة أيضًا؛ لا تستبدل تصدير Godot الرسمي عند إدخال أصول مستوردة أو أصناف عامة.
